1. Einstieg

  1. Arena: Öffne „Code-Labor“ oder das Code-Symbol neben einem Teilnehmer. Algo Sim: Wähle ein Verfahren und klicke „Code-Editor öffnen“.
  2. Wähle im Editor einen eingebauten Algorithmus. Der Quellcode wird als bearbeitbare Kopie geladen. In Algo Sim steht dort ausschließlich das gewählte Verfahren, etwa astar.js oder bfs.js.
  3. Für einen eigenen Routenalgorithmus wähle „Eigenen Algorithmus bauen“. Das Codefeld ist leer; definiere darin function findRoute(graph). Ein vollständiges Beispiel steht in Abschnitt 5.
  4. Ändere den Code, vergib einen Namen, klicke „Prüfen“ und anschließend „Speichern“. Die Variante ist danach in der passenden Algorithmusauswahl verfügbar.

Eingebaute Originale werden nicht überschrieben. Bei einer gespeicherten Variante aktualisiert „Speichern“ diese Variante; „Als neue Kopie speichern“ legt einen weiteren Eintrag an. Der Wechsel der Code-Auswahl ersetzt den Entwurf: wichtige Änderungen vorher speichern oder exportieren.

2. Regeln der Arena

  • Jeder Teilnehmer besitzt einen bewegten Punkt. Jede erstmals betretene Zelle gibt einen Punkt, einschließlich der Startzelle.
  • Reguläre Züge gehen eine Zelle nach oben, rechts, unten oder links. Belegte Zellen, Hindernisse und Grenzen sind gesperrt. Eingeschlossene Flächen geben keine zusätzlichen Punkte.
  • Alle Teilnehmer entscheiden anhand desselben Zustands vor dem Schritt. Wählen mehrere dieselbe freie Zelle, entscheidet der Seed-Zufall. Verlierer warten diesen Schritt; ihre bereits aktualisierte memory bleibt erhalten.
  • Ohne freien Nachbarn beginnt der Punkt sofort einen automatischen Rücklauf zur nächsten freien Zelle. Er läuft sichtbar über benachbarte belegte Zellen, auch über gegnerische Spuren. Besitzer und Punkte bleiben dabei unverändert; andere Teilnehmer ziehen gleichzeitig weiter.
  • Während eines Rücklaufs wird eigener Code nicht aufgerufen. Danach setzt die Strategie mit ihrem bisherigen Speicher fort. Kein Teleportieren.
  • Die zusammenhängenden eingebauten Arenen enden bei 100 % Belegung. Die meisten Punkte gewinnen; Gleichstände sind möglich.

3. Arena-API: nextMove(state, memory)

nextMove entscheidet einen regulären Zug. state beschreibt den aktuellen Zustand; memory ist dein eigener Speicher, anfangs {}. Gib { direction, memory } zurück. Die Richtung muss gerade erlaubt sein. Lässt du memory weg, bleibt der bisherige Speicher erhalten.

Feld / Funktion Bedeutung und Verwendung
state.x, state.y
state.position 		Eigene Koordinaten ab 0; position ist { x, y }. x wächst nach rechts, y nach unten.
state.direction Aktuelle Richtung: "up", "right", "down" oder "left".
state.availableMoves Array erlaubter Richtungen, z. B. ["up", "left"]. Wähle eine davon, um einen ungültigen Zug zu vermeiden.
state.neighbors.right Direkter Nachbar als { x, y, type, free }. Entsprechend existieren up, down und left. free ist ein Wahrheitswert.
state.cell(x, y) Weitere Zellen abfragen: "free", "wall", "self" oder "opponent". Außerhalb gilt wall. Höchstens 512 Abfragen je Aufruf.
state.random() Seed-Zufall von 0 bis kleiner 1. Beispiel für einen Index: Math.floor(state.random() * moves.length).
state.id, state.score, state.step Teilnehmernummer ab 0, bisherige Punkte und globaler Simulationsschritt. Ein Schritt ist kein garantierter Punktegewinn.
state.width, state.height Logische Rastergröße, unabhängig von der Anzeigegröße.
state.afterReturn
state.returnTrips
state.returnSteps 		afterReturn ist beim ersten Aufruf nach einem Rücklauf wahr. returnTrips zählt Rückläufe, returnSteps deren Schritte ohne Punkte. Ältere Namen: restarted und restarts.
memory Eigener JSON-kompatibler Speicher bis 64 KiB, getrennt pro Teilnehmer. Keine Funktionen, DOM-Objekte oder zyklischen Referenzen speichern. 
// Geradeaus bleiben; bei einer Sperre einen freien Nachbarn wählen.
function nextMove(state, memory) {
  const moves = state.availableMoves;
  const direction = moves.includes(state.direction)
    ? state.direction
    : moves[Math.floor(state.random() * moves.length)];
  return {
    direction,
    memory: { decisions: (memory.decisions || 0) + 1 }
  };
}

Für eine neue Planung nach einem Rücklauf kannst du am Funktionsanfang if (state.afterReturn) memory = {}; verwenden. Der Spielkern validiert jeden Zug; eigener Code verändert den echten Spielzustand nicht direkt.

4. Algo-Sim-API: findRoute(graph)

findRoute berechnet eine ganze Suche in einem synchronen Aufruf. Der gerichtete Straßengraph wird einmal als schreibgeschützte Kopie übergeben. Eigene Arrays, Maps, Klassen und Hilfsfunktionen sind erlaubt.

Feld / Funktion Bedeutung und Verwendung
graph.start, graph.target
graph.nodeCount 		Start und Ziel als Knoten-Indizes ab 0 sowie Anzahl der Knoten.
graph.nodes[v] Koordinaten { id, lat, lon }. Achtung: id ist die originale OSM-ID; v ist der für die Suche verwendete Array-Index.
graph.arcs[e] Gerichtete Kante { from, to, length }. e ist die Kanten-ID, from/to sind Knoten-Indizes, length ist die Länge in Metern.
graph.outgoing[v]
graph.incoming[v] 		Arrays von ausgehenden bzw. eingehenden Kanten-IDs. Vorwärtssuche nutzt outgoing; Rückwärtssuche nutzt incoming und folgt jeweils arc.from.
graph.neighbors(v) Ausgehende Kanten direkt als Objekte { id, from, to, length }. Alternative zum Zugriff über outgoing und arcs.
graph.heuristic(v) Luftlinie von v zum Ziel in Metern. A* priorisiert Entfernung vom Start + Luftlinie; Greedy nutzt nur die Luftlinie.
graph.createQueue() Erzeugt eine leere Min-Prioritätswarteschlange. q.push(v, p) fügt Knoten v mit Priorität p ein. q.pop() entnimmt den kleinsten Eintrag als { node, priority }; q.peek() liest ihn. Beide geben bei leerer Schlange null zurück. Mehrfache Einträge sind erlaubt: abgeschlossene Knoten beim Entnehmen überspringen.
graph.trace(v, e = -1, side = 0) Eine Expansion für die blaue Suchspur aufzeichnen. e ist die zum Knoten v führende Vorgängerkante; -1 zeichnet keine Kante. Bei Rückwärtssuche gilt side=1: e führt von v zur rückwärtigen Vorgängerposition.
return { path: [...] } Kanten-IDs in Reihenfolge vom Start zum Ziel, keine Knoten-IDs. Ein leeres Array ist nur bei Start = Ziel gültig.
return { path: null } Der Algorithmus hat keinen Weg gefunden. Das ist seine Aussage und kein unabhängiger Beweis für Unerreichbarkeit.

Der Kern prüft Kantenrichtung, Zusammenhang und Zielerreichung und berechnet die Strecke selbst. Ohne trace-Aufrufe erscheint nur die grüne Route; die Zahl expandierter Knoten bleibt 0. Ältere Strategien dürfen stattdessen die gleich langen Arrays traceNodes, traceEdges und traceSides zurückgeben; diese haben Vorrang vor trace-Aufrufen.

Die sechs Originale verwenden dieselbe API wie eigener Code: Dijkstra, A* und bidirektionaler Dijkstra minimieren Meter; BFS minimiert Kanten. DFS und Greedy garantieren keine kürzeste Strecke. Für die Prioritätswarteschlange kannst du auch eine eigene Implementierung schreiben.

Die Tabelle am Ende von Algo Sim vergleicht alle eingebauten und gespeicherten eigenen Algorithmen automatisch mit denselben Endpunkten. „Mehrweg“ ist die zusätzliche Strecke gegenüber Dijkstra; „Kürzeste Strecke?“ bewertet nur den aktuellen Weg. Die allgemeine Garantie steht unter dem Namen. Bei neuen Punkten oder geändertem Code werden die Werte neu berechnet; der Vergleich ist abbrechbar und exportierbar. Laufzeiten sind geräteabhängige Richtwerte.

5. Beispiele für eigene Wegsuchen

Breitensuche: wenige Kanten

Die Warteschlange wird von vorn gelesen. Jeder neu entdeckte Knoten bekommt eine Vorgängerkante. Am Ziel werden diese Kanten rückwärts gesammelt und anschließend umgedreht. 

function findRoute(graph) {
  const queue = [graph.start];
  const seen = new Set(queue);
  const previous = new Map();

  for (let i = 0; i < queue.length; i++) {
    const node = queue[i];
    graph.trace(node, previous.get(node) ?? -1);
    if (node === graph.target) {
      const path = [];
      for (let v = node; v !== graph.start;) {
        const edge = previous.get(v);
        path.push(edge);
        v = graph.arcs[edge].from;
      }
      return { path: path.reverse() };
    }
    for (const edge of graph.outgoing[node]) {
      const next = graph.arcs[edge].to;
      if (seen.has(next)) continue;
      seen.add(next);
      previous.set(next, edge);
      queue.push(next);
    }
  }
  return { path: null };
}

Prioritäten verändern: Dijkstra und A*

Öffne Dijkstra im Editor. Seine Warteschlange bevorzugt den kleinsten bisher bekannten Weg candidate. Mit dieser Änderung erhältst du die A*-Priorität: 

// Dijkstra:
queue.push(arc.to, candidate);

// A*: bisheriger Weg plus geschätzter Restweg:
queue.push(arc.to, candidate + graph.heuristic(arc.to));

Die Luftlinie überschätzt die verbleibende Straßenlänge nicht. Ein größerer Faktor vor der Heuristik kann die Suche stärker zum Ziel lenken, nimmt ihr aber diese Optimalitätsgarantie. Speichere Experimente unter eigenen Namen und behalte die Originale als Vergleich.

6. Prüfen, speichern und ausführen

  • Prüfen: Arena-Code erhält drei Probeaufrufe; Routen-Code einen kleinen gerichteten Probegraphen. Das findet Syntax- und grundlegende Rückgabefehler, beweist aber keine allgemeine Korrektheit.
  • Speichern: Prüft den Code und legt ihn lokal in der passenden Bibliothek ab. In der Arena danach als Teilnehmer wählen; in Algo Sim wird die gespeicherte Variante ausgewählt. Vor dem Spielen auf „Suche starten“ bzw. „Neuen Kampf starten“ klicken.
  • Import / Export: Sichert Name und Code als JSON. Arena und Algo Sim verwenden getrennte Formate. Browser-Speicher ist keine Sicherung; zum Gerätewechsel exportieren.
  • Auf Vorlage zurücksetzen: Arena lädt das Zufallsbeispiel; Algo Sim leert das Codefeld für einen neuen Algorithmus.
  • Abbrechen: Stoppt eine Prüfung oder laufende Berechnung. Danach kann sofort neu gestartet werden. Pause und Spulen betreffen nur die Wiedergabe.

7. Fehlerhilfe und reproduzierbare Ergebnisse

Meldung / Beobachtung Prüfe zuerst
Funktion fehlt / Syntaxfehler Heißt sie nextMove bzw. findRoute? Stimmen Klammern und Anführungszeichen? Kein import oder await verwenden.
Ungültige Richtung direction aus state.availableMoves wählen; nicht ungeprüft eine feste Richtung zurückgeben.
Unverbundene oder falsch gerichtete Kante path muss Kanten-IDs enthalten. Die erste Kante beginnt am Start; jede folgende am Ende der vorherigen; die letzte endet am Ziel.
Ziel nicht erreicht / leeres path Leeres Array nur bei Start = Ziel. Für „kein Weg gefunden“ path:null zurückgeben.
Keine blaue Suchspur graph.trace beim Expandieren aufrufen und die Vorgängerkante mitgeben.
Zeitlimit Endlosschleifen, fehlende seen-/closed-Prüfung oder wiederholte Vollsuchen vermeiden. Nach Abbruch mit kleinerem Beispiel prüfen.
Änderung wird nicht verwendet Speichern, gespeicherte Variante auswählen und eine neue Berechnung starten. Ein vorhandenes Replay ändert sich nicht.

Für reproduzierbare Arena-Vergleiche Seed, Form, Auflösung, Teilnehmerreihenfolge und Code beibehalten; nur state.random() als Zufall verwenden. In Algo Sim dieselbe Stadt und dieselben Endpunkte verwenden. Einzellaufzeiten schwanken mit Rechner und Browser.

Eigener Code läuft außerhalb der Oberfläche in einem Worker unter isolierter Herkunft, ohne Netzwerk- oder Browser-Speicherzugriff. Zeitlimit und Abbruch beenden die Ausführung. Browserfehler oder absichtlich extreme Speichernutzung sind damit nicht vollständig ausgeschlossen. Verwende eigenen oder vertrauten lokalen Code.

Algo Sim nutzt reale OpenStreetMap-Innenstadtausschnitte und ein vereinfachtes Pkw-Modell: Einbahnstraßen und gesperrte Wege, aber keine Abbiegeverbote oder Live-Verkehrsdaten. Es ist eine Simulation, keine Navigationsanwendung.
